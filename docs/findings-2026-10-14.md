# X-S10 Ver.3.11 固件只读初查（2026-10-14）

## 范围与安全边界

用户提供 X-S10 实机，研究主机 Ubuntu 24.04.5 LTS。**只读静态分析**；没有刷写相机、改动 SD 卡、发送厂商私有 USB 命令或运行未知固件补丁。公开仓库不包含原厂固件及二进制。

## USB 观察

- Ubuntu 识别相机为 `04cb:02ea`，产品名 **USB PTP Camera**。
- 标准 Imaging / Still Image Capture / PTP 类接口（一个 bulk IN、一个 bulk OUT、一个 interrupt IN）。
- 这是 USB 枚举成功的证据，**不是**已获得访问 ROM、RAM 或编程权限的证据。
- 未读取或证实相机当前运行的固件版本。

### 解读

**积极迹象**：存在一组连续 HEVC 编码器调试文本，以及 4K 59.94p 的模式名称，值得优先查找视频配置表、功能条件判断和编码器初始化例程。

**反例/限制**：也发现 X-S10 对外不提供的 `RAW RECORDING` 菜单字符串，说明部分资源/代码可能在不同机型之间复用。`Firmware version does not match hardware!` 是编码器诊断字符串，不代表在 X-S10 上确实触发了该错误。静态文本不能证明编码器连接到了 X-S10 视频处理链，不能证明 4K60 / 10-bit 内录可用。

## 下一阶段的可证伪问题

1. **HEVC 组件是否被调用？** 先确定负载内模块结构和适当的加载基址，Ghidra 反汇编并从编码器相关字符串追踪交叉引用和硬件初始化。
2. **10-bit 是编码器编译支持还是硬件支持？** 找位深/profile/像素格式选择及硬件版本检测分支；仅凭提示字符串无法判断。
3. **4K59.94 模式字符串是否被 X-S10 的配置选择器引用？** 对比固件中录制模式数据表、传感器时序、HDMI 和 SD 视频路径。
4. **有哪些配置仅出现在 X-T4、而未出现在 X-S10？** 在合法和许可条件允许下，获取 X-T4 官方固件做相同的离线解析和版本匹配的差异分析。

在可靠的物理恢复方案及具体硬件映射不存在之前，不尝试实机刷写。
