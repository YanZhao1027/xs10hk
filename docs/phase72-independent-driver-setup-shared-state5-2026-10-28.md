# 第72阶段：独立接口驱动启动链消费Phase71状态5，仍未形成实时回调调用边（2026-10-28）

## 本阶段取得的新连接及证据级别

Phase71 已通过原厂 ARM/Ghidra 在 X-S10 v3.11 和 X-T4 v2.12 闭合接口响应事件`0x1795/0x17A7`经任务队列`0x61`、事件表状态4回调、进入**状态5**的条件式静态路径。**本阶段确定另一条独立的接口/HD驱动启动链确实读取同一状态字节，并把状态等于5及另一运行态标志等于1作为硬件驱动初始化分支条件。**这是一条跨两个函数群的**共享运行态状态条件**，**并未找到从Phase71回调直接调用该驱动入口的同步BL**；执行顺序、竞争、是否真正启动仍需确认。

## 2. Phase71的状态字节确实是独立驱动路径的准入条件

驱动函数不是一条无条件的“硬件启用”例程：

- X-S10 `FUN_0126C388` 会先检查 `DAT_01C84F88 == 5`，然后还有`DAT_01C84FB4 == 1`这个独立的状态门；Phase71的事件表回调`FUN_0126BDC4`曾写入前一个相同字节的值**5**，却并未证明后一个门一定为1。
- X-T4 `FUN_012425A0` 与之同构，检查**`DAT_01BE5054 == 5`**以及**`DAT_01BE5080 == 1`**；其对应的状态写入来自Phase71的`FUN_01241FDC`。两机的状态字节地址不同但逻辑同构。
- 独立驱动函数同时协调队列/任务`0x61`，还通过同步/释放调用操作另一模块，X-S10是 **`0x35`**，X-T4是 **`0x37`**。这些编号**不能跟Recorder模块7、接口事件ID、接口描述符行号或Movie模式矩阵行号混为一谈**。
- 在上述分支下能看到使用`0xFFF7B000`接口标识的真实初始化/驱动调用、缓冲区和多轮出错/重试逻辑。**这里没有执行这些调用**，只是读取原厂ARM/Ghidra；地址及数据不构成可用于实体X-S10的改写操作建议。

静态证据更进一步明确了**两个不同的“必要条件集合”**：Phase71事件回调仅保证其函数进入时可以将状态设为5；本Phase72设备初始化要求另外一组独立设置过程成功，并由驱动调用时**重新读取**状态是否仍为5及另一个标志是否为1。即使两个函数都存在，**没有实时事件投递、成功回调、传感器时钟/宽高/ISP、VPU反馈或同一事务中的跨线程同步证据**，不能把二者当作已经完整实现的4K60/HEVC Main10录像链。
