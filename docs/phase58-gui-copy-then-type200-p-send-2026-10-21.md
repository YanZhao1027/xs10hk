# 第58阶段：GUI菜单配置真实整块复制进Recorder `0x200`输入P，随后按原始ARM控制流发送（2026-10-21）

> **当前最强上游证据**：X-S10 3.11和X-T4 2.12原厂固件各有配置初始化流程，在一个**特定条件分支**中，先将固定GUI录像配置结构完整`memcpy`到第57阶段`0x200`消息调用者所指定的独立输入缓冲区P，再以**原始ARM无条件向后跳转**进入同一函数中已核验的0x200消息发送调用。GUI菜单`eMode4kOut`（+0x581）和`eModeMovieCodec`（+0x5B0）均在拷贝长度内。随后Phase57/54/32/49已分别核实**条件式**消息体指针进入描述符+0x10、由type0x200初始化器取P、将P的两个输入字段映射至Recorder活动模板。因此“GUI -> Recorder P”的**有条件静态ROM数据流**不再缺失；仍无实机值或执行日志，不能声称4K60/Main10已解锁。

## 数据源、目的和精确ARM控制流（重点：往回跳转）

| 项目 | X-S10 原厂3.11 | X-T4 原厂2.12 |
|---|---|---|
| GUI源结构 | **`0x01B880A0`** | **`0x01AF2808`** |
| P配置输入目的结构 | **`0x01B5375C`** | **`0x01ABD79C`** |
| 复制包装器 | `FUN_0114F164` | `FUN_0112373C` |
| 包装器原始`MOVW R2,len` / 真`memcpy` BL | **`0x0114F16C/70`**：0x5DC=1500B | **`0x01123744/48`**：0x5D8=1496B |
| 同函数先复制后发送的上级初始化函数 | **`FUN_01F0C820`** | **`FUN_01E6AB64`** |
| `MOVW/MOVT R1`构造GUI来源 | `0x01F0CA80/84` | `0x01E6ACF8/FC` |
| `MOVW/MOVT R0`构造P目的 | `0x01F0CA88/8C` | `0x01E6AD00/04` |
| `BL`进行整块GUI→P复制 | **`0x01F0CA90` → `FUN_0114F164`** | **`0x01E6AD08` → `FUN_0112373C`** |
| **复制后无条件B反跳** | **`0x01F0CA94` → `0x01F0CA18`** | **`0x01E6AD0C` → `0x01E6AC90`** |
| 反跳到原始`BL`调用`0x200`发送入口 | `0x01F0CA18` → `FUN_02056240` | `0x01E6AC90` → `FUN_01FB21DC` |
| 后者实际提交P给0x200组装器 | `0x02056304`→`FUN_02197D94` | `0x01FB22A0`→`FUN_020EADF0` |

**重要的控制流反转陷阱：**原始ROM的复制BL地址*数值大于*上级发送BL地址，因为复制块在固件代码中位于后面，通过ARM `B`跳转回前面的共用发送尾段。单纯按机器地址排序会错误写成“先发送后复制”；本阶段原始A32 `MOVW/MOVT` + `BL` + `B` + `BL`检验明确保证是**先复制，再返回发送**。还存在另一条不先拷贝就发送的上级分支（XS10 `0x01F0C9CC`、XT4 `0x01E6AC44`），绝不能拿它们当作本段的拷贝后调用。

`FUN_0114F164` / `FUN_0112373C`本身直接调用原厂的 `FUN_012A9148` / `FUN_01281848` 真复制引擎，参数方向**dest=R0，src=R1，len=R2**，已从原始ARM、Ghidra及以前Phase26/53相互确认。至少还各有两个独立UI配置函数做相同方向GUI→P复制：XS10 `FUN_0118BB1C`/`FUN_020B2874`；XT4 `FUN_0115F34C`/`FUN_0200DEC0`。这些额外调用的**触发条件各异**，不是每次菜单修改无条件写入。

两机另有真实**反向**复制：XS10 `FUN_0205B284` 中`FUN_0114F164(&GUI,&P)`，XT4 `FUN_01FB7408` 中`FUN_0112373C(&GUI,&P)`。本阶段原始ROM也检查反向`MOVW/MOVT`参数与BL，强调“存在同大小内存拷贝”不能证明它是P的上游写者。

这条ROM中的数据传递**证明了两种配置结构的内容在指定调用路径下可以对应**，但**没有**证明用户所用机身在某次操作中进入了该路径、传递哪一个具体字段值、后续另有覆盖/归一化、真实队列成功、4K59.94 sensor/ISP读取、HEVC Main10 SPS、持续写卡性能或该机能够安全运行修改后的固件。配置flag语义更可能还与HDMI/视频输出有关，不能把`+0x581`称作“4K60 unlock bit”。
