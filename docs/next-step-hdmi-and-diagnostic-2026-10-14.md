# 下一步：将 10-bit HDMI 与 10-bit 机内编码分开验证（2026-10-14）

## 为什么 Atomos 10-bit 不等于机身内录 HEVC Main10

富士 X-S10 官方 [Movie Setting 手册](https://fujifilm-dsc.com/en/manual/x-s10/menu_shooting/movie_setting/) 明确指出：

- 机内写 SD 的视频为 **H.264，4:2:0 8-bit**；
- 在相应配置下，通过 HDMI 输出 **4:2:2 10-bit**；
- 菜单中的文件格式仅列出 MOV/H.264 与 MP4/H.264，不列出 MOV/H.265。

与之对应，[X-T4 官方手册](https://fujifilm-dsc.com/en/manual/x-t4/menu_shooting/movie_setting/) 列出 MOV/H.265(HEVC) LPCM，明确为 **SD 内录 4:2:0 10-bit**。

外置 Atomos 接收的是 HDMI 视频信号，并可通过其**自身的硬件和固件**编码为 ProRes / DNx / 部分机型 H.265 等格式；这条路径不需要 X-S10 完成机内 HEVC 10-bit 压缩编码。

因此，X-S10 的 HDMI 10-bit 是其前端采集/ISP/输出链路拥有高位深能力的有力证据，**不构成**机身内录编码器具备 Main10、硬件使能正常、写卡链路完成的证据。

更有价值的是：此前本项目已经验证两个指定版本的固件各有一段 **425,984 字节逐字节相同**的 HEVC 编码器候选区。下一阶段必须验证 X-S10 的 V61 驱动初始化与主程序的调用路径，而不是仅补菜单字符串。

### 不能由一个标记推出的事

- 同一套微码存在 ≠ X-S10 一定在运行或能初始化它。
- `H.265 MP Encoder` ≠ 已识别为 HEVC Main10；`MP` 的厂家具体含义尚未确定。
- 相机支持 Full HD 59.94p ≠ 支持 4K59.94p 的传感器读取、处理/HDMI 时钟和编码性能。
- 录机可录 4K60 ≠ X-S10 的 HDMI 源能送 4K60。

## 两条可推进的研究路线

### A：无机身介入的固件静态研究（默认）

1. 完善 X6 固件段识别，目前 X-S10 3.11 与 X-T4 2.12 各识别四个压缩段头及对应压缩率。
2. 获取可核验、适用的 X6 LZ 解码器及加载映射规则。目前 [fffw / ffun](https://github.com/tiredboffin/fffw) 的主要解码/ELF 转换组件尚未完整开源。
3. 将解出的主程序真实区段映射到 Ghidra，找到并交叉验证 V61 驱动加载 / HEVC 初始化 / Main10 profile / 功能校验 / SD 媒体管线之间的关联。
4. 在相同处理方式下对比 X-T4 主程序，查明 X-S10 额外的限制是否位于 UI、系统策略、驱动、硬件或其组合。

本路线风险最低、无须相机连接，但压缩解码可能需要较长的逆向研究。

### B：自愿选择的实机诊断 / RAM 读取

研究者 [fffw 的 Route 0xff80 笔记](https://github.com/tiredboffin/fffw/wiki/Route-0xff80) 记录了一种富士维修诊断 USB 模式，一些机型无需刷机就能读取 RAM 中的已解压程序；其开源工具提供 `info` 和 `ram read`，**也同时具有危及机身设置的写入、校准及执行命令**。

注意：**没有证据证明 X-S10 3.11 已在此模式下测试通过**。维修模式可能导致异常、卡死或重启；部分内存访问可能失败；即使读取成功也可能获得敏感的序列号/校准信息。

基于此，绝不默认启用。若用户明确愿意：
- 首先只由用户手动切换设备状态，然后在 Ubuntu 上以 `lsusb` **检查 USB VID/PID（不发厂商数据包）**，确认 `04cb:ff80` 是否出现；
- 只有在确认 VID/PID 和用户再次同意后，审核 `ff80 info` 的代码路径并尝试最小化、只读的交互；
- 读取 RAM 之前还应先确认适用于 X-S10 的内存范围及故障退出办法；
- **禁止**向摄像机执行 `write`、`cfgdata save`、`load`、`exec`、校准、固件升级或其他修改型指令；
- 不向公开 GitHub 上传 RAM dump、含机身序列号或校准数据的原始日志。

目前 USB 未检测到相机，不能开展路线 B；无需为路线 A 而重新接线。

## 额外可选：录机样片元数据核对

在用户自行拍摄了 Atomos 样片后，可以在 Ubuntu 本地使用 `tools/probe_recording.sh`，仅输出视频轨道的 codec、pixel format、分辨率和帧率等数据。

**注意**：外录文件为 10-bit 像素格式只能证明**最终文件存储格式**，不能单独证明 HDMI 输入没有经过升位填充；若要核实 HDMI 信号真实参数，还应以 Atomos 的输入状态页面与富士官方 HDMI 输出说明为准。

## 当前安全边界

原厂二进制与解码内容只在 Ubuntu；无需刷写 X-S10。现阶段没有 HEVC/Main10 初始化链路的成功交叉引用或可安全应用的固件补丁。
