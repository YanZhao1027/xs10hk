# 第七阶段：X-S10 FF80 实际通信与只读配置测试（2026-10-14）

## 已成功完成的实机步骤

设备：Fujifilm X-S10。用户在正常拍摄模式下的标准 USB PTP `GetDeviceInfo` 返回 `DeviceVersion=2.10`，此前已重复验证。

用户亲自操作，相机在 FF80 模式出现**红色指示灯亮、屏幕黑屏**；随后用户执行了一次**正常关机 → 正常开机恢复拍摄 → 再次进入 FF80** 的循环。该结果证明该机身至少在这一次实验中能从特殊模式正常退出，不能推广为任意维修指令都安全。

通过 Ubuntu 的 `lsusb` 被动确认：

- 正常 PTP：`04cb:02ea`；
- FF80：`04cb:ff80`，USB 设备类型 Vendor Specific，接口含 Bulk IN 与 Bulk OUT；
- 电脑的临时 USB 权限仅为当前用户 `zyubuntu` 对**当前设备节点**的一次性 ACL，不修改相机配置、不添加长期 `udev` 规则。用户在自己的 Ubuntu 桌面中完成管理员认证；密码没有进入聊天或仓库。

### FF80 信息读取

在会话完整关闭的前提下，使用仓库的限制型 `tools/ff80_info_only.py` 读取：

| 标签 | FF80 返回 |
|---|---|
| Product Name（0x04） | `X-S10` |
| Firmware Version?（0x08） | `1.60` |
| Device Type（0x10） | `CAMERA` |
| Framework（0x40） | `1.00` |

**重要：** 标准 PTP 报告 `2.10`，FF80 标签 `0x08` 返回 `1.60`。研究者源代码将后者标记为 `FW Version?`，尚未弄清到底代表相机主固件、引导程序、备用组件或其它内部版本。因此**不允许仅凭标签反推真实主程序版本或地址**。不应因此直接刷固件。

### 固定配置地址的单字节只读测试

根据 [fffw/ffjlib.py](https://github.com/tiredboffin/fffw/blob/main/ff80/ffjlib.py) 对 `get_config_usb_debug()` 的实现，使用以下只读操作：

- FF80 命令：`0x001A0002`
- 子操作：`2`（read config）
- 固定偏移：`0xF7`
- 读取长度：**1 字节**

本次实机收到有效响应：

```text
FF80 configuration byte 0xF7 (READ ONLY): 0x00
USB debugging is OFF.
FF80 read session closed.
```

这项操作经过两份代码独立实现复测，结果一致。它属于**读取诊断接口内部配置字节**，不是下载 RAM 镜像，不改变任何调试开关。

参考研究源代码中，`ff80 ram read` 在执行时会调用 `set_config_usb_debug(1)`，若原值为 `0`，则**写入配置**并于成功结束后恢复。虽然注释将其描述为**RAM 中的配置更改**，但尚未在 X-S10 机身上独立验证此状态的持久化属性或异常恢复行为。

**所以本阶段明确停止：没有调用任何配置写入、RAM 读写、任意函数执行、EEPROM/NVRAM 保存或固件更新。**

### 后续风险关卡与优先顺序

1. **首先明确版本与内存映射。** 通过本机 UI 显示的机身固件版本或其它正式途径核对 `2.10` / `1.60` 的含义；不能把离线 X-S10 **3.11** 固件的文件偏移误用成当前运行内存地址。
2. 尽可能通过脱机文档与代码分析找到 FF4230 / X-S10 已验证的普通 RAM 范围，避免读到内存映射硬件寄存器（MMIO）。
3. 如果之后仍要使用原版 `ff80 ram read` 风格路径，必须再次征得机主对**临时修改配置字节 `0xF7` 并恢复**的明确授权，并设计成功、超时和异常时的恢复检查。不能把工具源码中的“write to RAM”注释当成永久安全的保证。
4. 在没有具体安全范围前**不进行全 RAM 扫描**；在没有本机验证恢复路径前不尝试修改固件。
5. 结束实验时由机主正常关闭电源、断开 USB、确认正常拍摄模式可再次启动。临时 USB ACL 将随设备重新枚举/断开而消失。

不公开原厂固件、RAM 镜像、设备序列号或原始设备配置数据。
