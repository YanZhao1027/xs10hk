# 第49阶段：Recorder 模式状态 +0x581 从输入缓冲区到活动配置与父对象 +A8E 的正向静态链（2026-10-20）

> **本阶段新增且经原厂指令直接核实的证据**：X-S10 原厂 3.11 与 X-T4 原厂 2.12 的 Recorder 配置转换器各有连续 **8 条 A32 LDRB/STRB**，将输入缓冲区偏移 `+0x581/+0x580/+0x583/+0x582` 分别转存到固定中间结构 `+0x3FC..+0x3FF`（X-S10）／`+0x400..+0x403`（X-T4）。先前第32阶段证实同一中间结构经调用链被传入 `0x478/0x47C` 字节的活动模板拷贝；第48阶段证实活动模板中的 `0x01C251D4/0x01B83940` 是 4K 父对象 `+0xA8E` 的真实 getter 来源。**由此连通了原始配置输入 `+0x581` → Recorder 活跃 flag → 4K 模式键条件覆盖的静态路径，但仍没有找出输入 `+0x581` 的最初填写者或任何实体运行时值。**

所有结论仅针对 Ubuntu 的 **未修改原厂 X-S10 3.11 / X-T4 2.12** 固件和既有只读 Ghidra 项目。历史实体 X-S10 是 **2.10**。没有连接、诊断或修改实体相机，没有 USB/FF80、RAM/Flash 操作、固件打包/补丁/刷写；也没有推导出 4K60、Main10 解锁能力。

## 一、对应的正向配置通路

两机在 **同一个** Recorder 转换器中执行以下映射：

| 原始配置输入偏移（取自描述符指向的缓冲区 P） | X-S10 中间偏移 | X-S10 活动 RAM 字节 | X-T4 中间偏移 | X-T4 活动 RAM 字节 |
|---|---|---|---|---|
| `P+0x581`（父对象 `+A8E` 的 flag） | `+0x3FC` | `0x01C251D4` | `+0x400` | `0x01B83940` |
| `P+0x580`（相邻 companion） | `+0x3FD` | `0x01C251D5` | `+0x401` | `0x01B83941` |
| `P+0x583`（同一配置的后续字节） | `+0x3FE` | `0x01C251D6` | `+0x402` | `0x01B83942` |
| `P+0x582`（同一配置的后续字节） | `+0x3FF` | `0x01C251D7` | `+0x403` | `0x01B83943` |

这里的 **P 是输入描述符 `+0x10` 保存的指针值**，不是描述符本身，也不等于某个已知静态 ROM 地址。第32阶段已核对：X-S10 描述符 `0x02D987E8`，指针字段 `0x02D987F8`；X-T4 描述符 `0x02D0BF48`，指针字段 `0x02D0BF58`。初始化器读取 P 作为 `FUN_012C9500` / `FUN_012A313C` 的第二参数，在后续调用模板更新器时交出同一个固定中间结构。

固定中间结构 X-S10 `0x02D9CC60`、X-T4 `0x02D103B0`。对应活动 Recorder 模板基址 X-S10 `0x01C24DD8`、X-T4 `0x01B83540`。因此两个地址恒等式在原厂中分别成立：

    X-S10: 0x01C24DD8 + 0x3FC = 0x01C251D4
    X-T4 : 0x01B83540 + 0x400 = 0x01B83940

同一结构内 Codec 仍是独立的字段：X-S10 的输入 `+0x5B0` → 中间 `+0x430` → 活动 `0x01C25208`；X-T4 输入 `+0x5B0` → 中间 `+0x434` → 活动 `0x01B83974`。**Codec 活动字段比这里的 flag 高 `0x34` 字节，不可混称。**

## 二、16 条新的原始 Section1 A32 字节指令

与第20阶段已保存的完整 Ghidra 反编译独立交叉验证，本阶段从 SHA 固定的两份原始 Section1 中读取、逐一断言了 **每机 8 条、共 16 条**连续机器指令，严格检查寄存器、立即数偏移、读写方向与顺序。

| 数据传递 | X-S10 原始 A32 LDRB / STRB 地址 | X-T4 原始 A32 LDRB / STRB 地址 |
|---|---|---|
| `input[0x581] → intermediate[flag]` | `0x012C9914 / 0x012C9918` | `0x012A3560 / 0x012A3564` |
| `input[0x580] → intermediate[flag+1]` | `0x012C991C / 0x012C9920` | `0x012A3568 / 0x012A356C` |
| `input[0x583] → intermediate[flag+2]` | `0x012C9924 / 0x012C9928` | `0x012A3570 / 0x012A3574` |
| `input[0x582] → intermediate[flag+3]` | `0x012C992C / 0x012C9930` | `0x012A3578 / 0x012A357C` |

实际 ARM 编码的 `LDRB R3,[R5,#0x581]` 在两机皆为 `E5D53581`；相应 `STRB R3,[R4,#0x3FC]` (X-S10)／`STRB R3,[R4,#0x400]` (X-T4) 分别为 `E5C433FC`／`E5C43400`。接着其他三对依次将 `0x580/0x583/0x582` 放进连续目标位置。四组偏移**不是升序**，不能误读成 memcpy 连续四字节；它是专用字段重排。

Ghidra 在 X-S10 `FUN_012C9500` 与 X-T4 `FUN_012A313C` 的完整反编译中，也逐字显示了以上四行输入→输出赋值。原始机器字独立审计避免只根据 C 变量名或输入输出拥有相同偏移而错误闭环。

## 三、与第32/47/48阶段的经验证连接

第32阶段已逐机验证：

1. 配置主函数从描述符 `+0x10` 获取输入 P，再以 P 调用上述字段转换器；转换器的目的指针是固定中间结构。
2. **同一初始化器随后**调用模板更新器。其传递中间结构指针给 X-S10 `FUN_012BD110`／X-T4 `FUN_01295780`，后者使用 A32 寄存器约定将 `0x478/0x47C` 字节拷入活动模板。两段覆盖本次 `flag..flag+3` 字节，也覆盖此前审计的独立 Codec 字节。
3. 第32阶段已验证的 ROM Section2 常量、BL 目标、中间结构与活动地址恒等式、本地静态 READ xrefs 在本阶段**重新运行**，不是仅复制旧结论。

第48阶段本轮也已重新运行：原始 Section1/2 SHA、父对象池动态槽初始化、`FUN_012BD7D0`/`FUN_01295E44` getter、原始 BL/LDRB、`+A8E` 字段写入、活跃 RAM 源地址及反向导出均通过。第47阶段条件检查为：录像类型 4、5、6、7 **且** `parent+A8E == 1`，才把两个字节组成的模式键低位改写为 6，否则原值保持不变。静态表可因此选到不同的 1080/4K 候选行，**不是硬件实际分辨率变化观察**。

此时得到的**带条件静态链**是：

    当前配置输入缓冲区 P[+0x581]（初值未知）
       -- A32 LDRB/STRB --> 固定中间结构[+0x3FC / +0x400]
       -- 经已确认配置更新调用与复制参数 --> 活动 Recorder flag
       -- 真实 getter --> 动态父对象[+0xA8E]（仅4K类型，其他类型=0）
       -- 仅 flag==1 的条件 --> Movie模式键低字节 = 6
       -- 原厂 96×64B 静态 LUT 的尺寸候选匹配

另一个独立的**反向导出**函数 `FUN_012BE684`／`FUN_01296D38` 会把活动状态四字节分别输出到 `+0x581/+0x580/+0x583/+0x582`。反向导出中的 `param_1` 是其输出参数，**不应与前向主输入指针 P 混为同一个动态对象**；不能从互相对应的映射推出实体机已完成运行态循环。

## 四、仍然缺失的决定性边

- **当前输入配置 P 的 `+0x581` 由谁最初写入／恢复／覆盖？** 当前原厂证据只能证明某条已有值进入活动配置，不能说明 X-S10 的 UI/型号检查会实际选到1、2或其他值，也不能把这个旗标命名为“4K60解锁位”。
- 前向中间结构写入与后续拷贝之间**可能存在其他函数修改或间接别名**；第32阶段所指向的低地址复制引擎没有在本轮固件映像里独立反编译，当前证明的是 ARM 参数、调用目标和静态复制路径，非逐帧实机观测。
- GUI 模式可达性、4K59.94 摄取、Sensor/ISP/时钟、V61 输入吞吐、实际 HEVC Main10 SPS及SD写卡能力均未确认。现有 X-S10 实体机历史版本 **2.10**，不兼容研究固件 **3.11** 的绝对地址。

**下一关**：从两机配置输入描述符 `+0x10` 所指缓冲区出发，追溯 `P+0x581` 的最初生产者，查默认值/模式切换/机型权限；必要时并行检索独立设置服务和结构体拷贝的别名，避免把随机结构的 `STRB #0x581` 当作同一个 P。必须有原始 ARM＋数据指针身份链，不能把“静态支持多种 flag”误当作相机可选功能。
